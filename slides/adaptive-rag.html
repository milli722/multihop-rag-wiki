先備知識

開始前，先懂兩個名詞

RAG 檢索增強生成

LLM 回答前，先從大量文件中找出相關段落，放進上下文，再生成答案。

好處：LLM 不知道的事，也能靠外部文件回答。

多步檢索 Multi-step Retrieval

檢索和推理交替好幾輪：每一輪用「原問題＋目前找到的東西」再去查，直到能回答。

多跳問題需要它：後面的證據要靠前一跳的答案才找得到。

① 背景：要做什麼

回答問題，有三種策略

策略寫法特性
A 不檢索ā = LLM(q)最快；LLM 不知道的事就答不出來
B 單步ā = LLM(q, d)先檢索一次，再回答
C 多步āᵢ = LLM(q, dᵢ, cᵢ)檢索、推理重複好幾輪；最強但最貴

q＝問題、d＝檢索到的文件、cᵢ＝前幾輪的文件與中間答案

👉 這篇要做一個能依每個問題，自動挑策略的問答框架。

② 動機：為什麼要做

一種策略打天下，不是浪費就是不夠

真實的問題有難有易

多數是簡單問題，例如「巴黎是哪國首都？」
偶爾才有複雜的多跳問題。

固定策略的代價

  • 每題都多步 → 簡單題浪費運算
  • 每題都單步／不檢索 → 複雜題答不好

既有的「適應式檢索」也不夠好

  • 依實體出現頻率決定要不要檢索 → 只有「要／不要」兩種，沒考慮多跳
  • 依模型輸出決定何時停止 → 太複雜，要跑好幾輪才停
③ 欲解決的問題

能不能「先判斷難度，再選策略」？

在回答之前，先判斷問題有多難，
再選最適合的策略，同時兼顧準確率與效率。

簡單LLM 自己答
·
中等查一次就夠
·
複雜才值得多步

  • 切換策略時不用改模型參數，只是走不同流程
④ 研究方法 2 · 關鍵技巧

沒有「難度」標註資料？自動產生

步驟 1：Silver data

三種策略都跑一遍，用「最簡單就答對的那種」當標籤。

例：不檢索就答對 → A；不檢索錯、單步和多步都對 → B（簡單的優先）

步驟 2：Dataset bias

三種都答錯的題目沒有標籤，就看它來自哪種資料集：

  • 單跳資料集 → B
  • 多跳資料集 → C

👉 不需要人工標註，用 cross-entropy loss 訓練分類器。

⑤ 核心概念：用來處理什麼

四個核心概念

概念用來處理什麼問題
適應式檢索不是每題都需要一樣多的檢索 → 依問題決定
問題難度 query complexity把「要不要檢索、檢索幾輪」轉成一個三分類問題
自動標註沒有現成的難度標註 → 用「模型答對與否」＋「資料集來源」代替人工

⑥ 實驗設計

混合簡單題與難題，模擬真實情境

資料集（每個取 500 題）

  • 單跳：SQuAD v1.1、Natural Questions、TriviaQA
  • 多跳：MuSiQue、HotpotQA、2WikiMultiHopQA

共用設定

  • 檢索器：BM25
  • LLM：FLAN-T5-XL (3B)、XXL (11B)、GPT-3.5

比較對象

  • Simple：不檢索、單步
  • Adaptive：Adaptive Retrieval、Self-RAG、Adaptive-RAG
  • Complex：多步
  • Oracle：Adaptive-RAG＋完美分類器（上限）

指標

  • 效果：EM、F1、Accuracy
  • 效率：Step（檢索＋生成次數）、相對時間

⑧ 研究缺口與限制

還缺什麼？

作者自己指出的

  • 沒有現成的難度標註資料，自動標註可能標錯
  • 和完美分類器差距很大（F1 62.80 vs 50.91），分類器架構還能改進
  • 只分 3 個難度等級

讀者可以再想的

  • 難度一開始就決定，過程中不再調整；判錯就沒有補救
  • 決定「查幾輪」，但沒處理「每輪放幾篇」
  • 檢索器只用 BM25

總結 · 自我檢測

一句話記住這篇

Adaptive-RAG 先用小模型判斷問題難度，再決定不檢索、檢索一次或多步檢索，用不到一半的時間達到接近多步的效果；但分類器準確率只有 54.52%，是最大的改進空間。

Q1. 分類器的訓練標籤是怎麼來的？

先看哪個最簡單的策略答對（silver data），都答錯的再依資料集是單跳（B）或多跳（C）來標。

Q2. 為什麼說「分類器是關鍵」？

換成完美分類器，F1 從 50.91 提升到 62.80，時間還更短。

Q3. 這個方法最大的弱點是什麼？

難度一開始就決定，判錯（例如 C 判成 B）就沒有機會補救。
